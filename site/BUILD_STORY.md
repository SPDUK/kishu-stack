# This site is a Kishu case study

The Kishu demo website in this repository was built using Kishu mode in Codex. The user explicitly confirmed that this work may be used as a real-world example in future site copy and demonstrations.

## The actual brief

The user invoked `kishu:kishu-mode` and asked to “build me a demo site showing off kishu mode,” with Japanese styling and an original chibi Kishu puppy that could serve as a website mascot, README mark and favicon.

That first request established the build. Follow-up direction confirmed the model preferences, enabled Kishu for this project, and chose local development with GitHub Pages as the intended hosting destination.

## What Kishu produced

- A responsive static website with Japanese-inspired typography, color and composition.
- An original full-body puppy and a compact head stamp, with transparent PNGs, optimized web artwork, favicon exports and light/dark README lockups.
- Three interactive, clearly labeled engineering walkthroughs with replay, scenario switching, keyboard navigation and host-specific commands.
- Eighteen passing tests for the demo controller, model-role requests, command mappings, and discovery generation.
- Browser inspection of desktop and mobile layouts, with supporting text and narrow-screen overflow corrected during verification.
- An independent design review with a `ship` verdict and no material fixes.
- A documented design system, self-hosted fonts, and relative asset paths checked for a GitHub Pages project subpath.

## Value-led revision

The follow-up brief removed the mascot showcase and download offer, kept the puppy as unnamed flair, and made model routing the central story. The hero now visualizes a focused planning-to-implementation handoff. The workflow overview identifies Kishu, pstack, conditional Impeccable guidance, and clear output. The three examples expose role assignments, bounded briefs, design checks, and honest remaining gaps. A local model-role playground updates the walkthrough and creates a setup request. It does not claim to execute models or report measured savings.

## Motion and discovery revision

The user asked for a polished feel with animated puppy details and soft page entrances, then confirmed `https://spduk.github.io/kishu-stack/` as the canonical public address. This revision added a bounded puppy greeting, a logo tilt, one-time section reveals, gentle FAQ answers, and explicit motion cancellation for reduced-motion preferences, focus, and page visibility. Browser checks found a rotated mascot outline extending a few pixels beyond a narrow viewport; its smaller-screen positioning was corrected.

The same revision added practical FAQs and a shared source for search descriptions, social metadata, structured data, the sitemap, and textual product references. A new 1200 × 630 social card carries the planning/build/review story. The website remains static, with no added runtime library. See [discovery decisions](DISCOVERY.md) for source guidance and the GitHub Pages robots-file limitation. Publication and indexing were not performed.

## Three briefs, one collection

The user asked for original image-generated MMO artwork, a simulated dark trading dashboard, and a contrasting third demo. The public collection contains Veldrift, Meridian and Stillroom. These are real Kishu builds for fictional products.

The main agent defined independent scopes and delegated each demo to a coding worker using the user's configured `gpt-6.1-sol` model with `xhigh` reasoning. The main agent owns generated assets, integration, the concise public story and release verification. The image-generation tool creates scenery and studio photography from authored prompts, with no reference images supplied.

[The visual story](dist/case-studies/mmo.html) focuses on what happened and why. [The decision record](mmo/DECISIONS.md) distinguishes the user's instructions, Kishu guidance, agent choices, tool execution and observed outcomes. Asset prompts are provenance; they are not a hidden reasoning transcript. Requested worker settings are recorded, but runtime model identity, token use, costs and savings are not measured.

All earlier third-party game artwork, footage, derivative screenshots and acquisition scripts were excluded before the public release. The current gallery uses original generated artwork and fresh screenshots of the new demos. The user authorized a new parentless release history before publication.
