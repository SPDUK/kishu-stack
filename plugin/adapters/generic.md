# Other harnesses

Follow Kishu using the host's available tools. The portable package is a skill plus its relative library and references; preserve the complete package when installing it. A harness that only accepts individual skills can use the standalone export.

Map inherited tool labels to actual capabilities instead of calling nonexistent Cursor tools. Read pstack role briefs as instructions when named subagent types are unsupported. Honor model preferences only when the host supports the requested IDs and parameters. Otherwise inherit the current model and disclose material limits on requested independent review.

Use existing browser, terminal, document, connector, and authoring tools. If a needed capability is missing, continue independent work and report the specific verification gap. Do not install unrelated tools merely because they appear in an upstream example.

User instructions can point directly to the public SKILL.md for always-on behavior. Skill-selection punctuation and plugin packaging vary by host; use the host's supported invocation and recognize `/kishu-mode` as an ordinary request to use this mode.
