### Investigation

Answer the user's question from relevant evidence. This route is read-only unless the user also asks for an implementation.

For a narrow question, inspect what is necessary and answer directly. Use `how` for unresolved subsystem architecture and `why` for motivation or history; reuse investigation already performed. Non-code research uses the relevant available sources and specialist skills.

Separate observations from inferences. Give a recommendation with concrete tradeoffs when the user asks for judgment. Cite sources near the claims they support and state material uncertainty. Do not create a code change, architecture exercise, plan document, or PR just to answer a question.

Use Kishu's communication policy rather than imposing the architecture-explainer format on every investigation.
